# HUMAN / AI 移动端视觉挑战游戏设计

日期：2026-10-08  
状态：已确认设计与实施计划，待开发
工作名称：`HUMAN / AI`  
核心文案：`你比 AI 更快吗？`

## 1. 产品目标

制作一个极简移动端 H5 游戏，让大众用户无需教程即可开始，在相同的 20 个固定关卡中与真实 AI 比较视觉判断速度。

产品需要同时满足：

- 前 1–5 关容易理解并快速建立成就感。
- 第 6 关切换到 9×9 后明显变难。
- 首次挑战时，约 90% 的玩家无法通过第 10 关。
- 玩家每关都能完整作答，AI 不提前揭晓答案。
- AI 使用真实 OpenAI Decisions API 答案、置信度和接口耗时，不人为放慢。
- H5 永远不直接访问 OpenAI；所有 Decisions 请求都经过独立部署的 Cloudflare Worker。
- 分享内容突出“到达关卡”和“比 AI 更快几关”。
- 页面极度简约，一屏只完成一个主要动作。

不做积分、装备、道具、复杂账户、好友房间和随机题库。

## 2. API 能力边界

每关使用一个 Decisions `choice` 问题，让 AI 从网格位置中选择唯一不同项：

- 3×3 提供 9 个候选位置。
- 9×9 提供 81 个候选位置。
- OpenAI Decisions API 的一个 `choice` 问题支持 2–255 个唯一候选项，因此两种棋盘都在限制内。
- AI 输入为与玩家看到的相同关卡图片，不传递正确答案或隐藏特征。
- 候选值使用 `r1c1`、`r1c2` 等稳定坐标；描述为 `row 1, column 1` 等位置语义。
- 当前 Decisions API 使用 `gpt-6-luna`。

官方资料：

- [Decisions API 指南](https://developers.openai.com/api/docs/guides/decisions)
- [Create a decision API reference](https://developers.openai.com/api/reference/resources/decisions/methods/create)

## 3. 核心游戏循环

### 3.1 开始一局

1. 首页只展示游戏名、核心问题、`20 关 · 3 条命` 和“开始挑战”按钮。
2. 点击后出现 3、2、1 倒计时。
3. 创建本局会话，生命值初始化为 3，从第 1 关开始。

### 3.2 单关流程

1. 客户端预加载关卡图片。
2. 图片正式显示时，玩家倒计时与 AI Decisions 请求逻辑同时启动。
3. UI 只显示“AI 正在寻找”，不展示 AI 是否已经完成。
4. 玩家点击一个格子后立即锁定答案；倒计时结束时自动判定超时。
5. 玩家提交后才揭晓双方结果。
6. 结果停留约 1 秒后自动进入下一关，玩家可以提前点击“下一关”。

玩家耗时从图片完成首次绘制开始，到有效点击发生为止。AI 对比耗时从游戏服务发起 Worker 请求开始，到游戏服务收到完整有效答案为止，包含 Worker 网络与 OpenAI 处理时间；Worker 另记录纯 OpenAI 请求耗时用于运维分析。两者分别使用各自的真实耗时；AI 速度仅用于人机对比，不参与排行榜。

### 3.3 胜负规则

- 玩家正确、AI 错误或拒答：玩家获胜。
- AI 正确、玩家错误或超时：AI 获胜，玩家扣 1 条命。
- 双方正确：耗时更短者获胜。
- 双方错误：本关无人获胜，玩家扣 1 条命。
- AI 超时、接口异常或返回非法候选项：显示“AI 掉线”，本关仍按玩家答案正常结算。

“比 AI 更快关数”只在双方都正确且玩家耗时严格小于 AI 耗时时增加。AI 答错、拒答或掉线时玩家可以赢得该关，但不会增加这一速度指标。

答错或超时后不重试当前关，直接进入下一关。生命耗尽立即结束；仍有生命时最多玩到第 20 关。

### 3.4 结算

结算页只突出：

- 到达关卡。
- 本局比 AI 更快的关数。
- 全服排名。

次要操作只有“生成战绩海报”和“再玩一次”。不展示综合积分。

## 4. 生命与重玩

- 每局固定 3 条命。
- 玩家答错或超时扣 1 条命。
- AI 答错不会恢复或增加生命。
- 允许无限重玩。
- 每次重玩都可以更新个人最好到达关卡并进入总榜。
- 固定关卡带来的记忆优势是被接受的玩法：第一次考察观察力，后续逐渐成为记忆与操作速度挑战。

## 5. 排行榜

排行榜唯一排序字段是个人最好到达关卡。

- 到达关卡更高者排名更高。
- 到达相同关卡的玩家完全并列。
- 不使用剩余生命、正确题数、击败 AI 次数或耗时破除并列。
- 所有完成第 20 关的玩家并列最高等级。
- 列表展示顺序可以稳定使用首次达到该关卡的时间，但该顺序不改变名次。

首版不要求登录。服务端通过匿名玩家 ID 保存个人最好成绩，浏览器本地保留恢复凭据。昵称为可选字段，不阻挡开始游戏。

## 6. 20 关关卡设计

### 6.1 首次挑战存活率目标

| 节点 | 目标存活率 |
|---|---:|
| 第 3 关后 | 95% |
| 第 5 关后 | 80% |
| 第 7 关后 | 45% |
| 第 10 关后 | 10% |
| 第 15 关后 | 1% |
| 完成第 20 关 | 低于 0.1% |

存活率只统计玩家的首次完整挑战，避免重玩记忆影响难度判断。

### 6.2 固定关卡表

| 关卡 | 棋盘 | 差异类型 | 玩家倒计时 |
|---|---|---|---:|
| 1 | 3×3 | 明显不同的 Emoji | 8.0 秒 |
| 2 | 3×3 | 明显颜色差异 | 8.0 秒 |
| 3 | 3×3 | 箭头方向不同 | 7.0 秒 |
| 4 | 3×3 | 缺少一个明显部件 | 7.0 秒 |
| 5 | 3×3 | 相似字符，例如 O/0 | 6.0 秒 |
| 6 | 9×9 | 明显图形异类，制造数量突变 | 7.0 秒 |
| 7 | 9×9 | 小角度旋转 | 6.5 秒 |
| 8 | 9×9 | 易混淆文字，例如 未/末 | 6.0 秒 |
| 9 | 9×9 | 少一条短线或一个小点 | 5.5 秒 |
| 10 | 9×9 | 轻微色差 | 5.0 秒 |
| 11 | 9×9 | 左右镜像 | 4.8 秒 |
| 12 | 9×9 | 缺口方向不同 | 4.6 秒 |
| 13 | 9×9 | 轻微旋转叠加颜色干扰 | 4.4 秒 |
| 14 | 9×9 | 内部留白位置变化 | 4.2 秒 |
| 15 | 9×9 | 复杂图标缺少一个小部件 | 4.0 秒 |
| 16 | 9×9 | 相似汉字的细微笔画差异 | 3.8 秒 |
| 17 | 9×9 | 镜像叠加低对比度 | 3.6 秒 |
| 18 | 9×9 | 多部件图形中的位置偏移 | 3.4 秒 |
| 19 | 9×9 | 低对比度微小缺口 | 3.2 秒 |
| 20 | 9×9 | 复合图形中 1–2 像素级差异 | 3.0 秒 |

### 6.3 难度控制参数

关卡难度由四个独立参数控制：

1. 搜索空间：第 6 关从 9 个候选骤增至 81 个。
2. 差异显著度：从类别差异逐步缩小到笔画、缺口和偏移。
3. 单格复杂度：后期图案包含更多内部部件和视觉干扰。
4. 时间压力：倒计时从 8 秒逐步压缩到 3 秒。

所有关卡采用“规则模板 + 冻结参数”的混合导演方式。开发期可以调整参数；正式发布后，同一关卡版本的图片、答案、位置和倒计时全部冻结。

### 6.4 公平性约束

- 每关严格只有一个正确答案。
- 图案预先渲染为统一尺寸图片，避免系统字体和浏览器抗锯齿差异。
- 差异必须在标准移动端屏幕上肉眼可见，不依赖图片压缩噪声。
- 颜色不是后期关卡的唯一判断依据；需要兼顾色觉差异用户。
- 玩家和 AI 获取同一张最终栅格图。
- 正确答案只保存在服务端，不写入前端关卡资源。

## 7. 移动端 H5 视觉设计

设计原则是黑白为主、单一强调色、无底部导航、无弹窗堆叠，一屏只保留一个主任务。

### 7.1 首页

- 左上角小字：`HUMAN / AI`。
- 主标题：`你比 AI 更快吗？`
- 规则摘要：`找出唯一不同。20 关，3 条命。`
- 唯一主按钮：`开始挑战`。
- 页底弱化显示：`固定 20 关 · 全服同题`。

### 7.2 游戏页

- 顶部左侧显示 `06 / 20`，右侧以三个实心圆表示生命。
- 中部只显示倒计时和棋盘。
- 底部显示 `AI 正在寻找` 和 `点击不同项`。
- 不显示菜单、排行榜入口、复杂进度动画或广告位。
- 触控格子覆盖完整单元区域，视觉图案可以小，但点击目标不能小。

### 7.3 单关揭晓页

- 主标题只显示 `你赢了`、`AI 赢了` 或 `AI 掉线`。
- 展示玩家与 AI 的正确性和耗时。
- 双方都正确时展示速度差，例如 `你快了 0.43 秒`。
- 显示 `本局你已有 3 关比 AI 更快`。
- 约 1 秒后自动进入下一关。

### 7.4 结算页

- 用超大数字展示到达关卡。
- 只补充“比 AI 更快几关”和全服排名。
- 主按钮为“生成战绩海报”，次按钮为“再玩一次”。

首版主要适配 360–430 CSS 像素宽的竖屏设备，同时保证桌面浏览器居中显示为手机宽度。

## 8. 分享策略

### 8.1 分享海报

海报使用 9:16 竖版极简布局，只包含：

- `HUMAN / AI` 品牌。
- 动态主标题。
- 最终到达关卡。
- `同样的 20 关，你能走到哪里？`
- 游戏二维码或短链接。

动态主标题规则：

- 击败 AI 至少一关：`我有 N 关比 AI 更快`。
- 没有击败 AI：`我到达了第 N 关`。
- 完成第 20 关：`我通关了 HUMAN / AI`。

### 8.2 分享链路

- 支持浏览器系统分享、保存海报和复制链接。
- 分享链接携带服务端签名的结果 ID，不能由前端直接伪造成绩。
- 好友打开后先看到分享者的到达关卡和击败 AI 次数，再点击“开始挑战”。
- 好友进入的仍是同一套固定 20 关，不创建独立题目、房间或挑战种子。

## 9. 系统边界与组件

### 9.1 H5 客户端

负责页面渲染、图片预加载、倒计时、点击采集、动画、结果展示和分享调用。客户端不持有正确答案，也不决定生命与最终到达关卡。

H5 只访问游戏站点的同源 API，不持有 OpenAI Key、Worker 鉴权密钥，也不直接调用 OpenAI 或 Cloudflare Worker。

### 9.2 游戏会话服务

负责创建匿名玩家、创建一局、推进关卡、校验单次提交、维护生命、生成最终结果和更新个人最好成绩。

### 9.3 关卡目录

每个关卡版本包含：

- 关卡 ID 和版本。
- 冻结后的图片资源。
- 棋盘尺寸。
- 正确位置。
- 倒计时时长。
- AI 候选位置列表。

前端接口只返回不含正确位置的公开字段。

### 9.4 Cloudflare Decisions Worker

独立的 Cloudflare Worker 是唯一可以访问 OpenAI Decisions API 的组件。游戏会话服务通过服务端共享密钥调用 Worker；该密钥和 OpenAI Key 都只通过部署环境的 Secret 注入。

Worker 负责：

- 校验服务端鉴权、请求体大小、图片格式和 9/81 个唯一候选位置。
- 把关卡图片和位置选项转换为 `POST /v1/decisions` 请求。
- 设置严格超时，不重试会导致重复计费的已发出请求。
- 验证答案必须属于候选集合，并返回统一的成功或错误结构。
- 只记录请求 ID、耗时和错误码，不记录密钥、完整图片或玩家数据。

游戏会话服务负责保存 AI 的选择、概率分布、置信度、耗时和错误类型。Worker 不接收正确答案，也不读写游戏数据库。

### 9.5 排行榜服务

按关卡版本维护每个匿名玩家的最好到达关卡，聚合同关卡人数，并计算并列名次。它不读取耗时或其他统计作为排序条件。

### 9.6 分享服务

根据签名结果 ID 输出分享落地页、动态 Open Graph 信息和 9:16 战绩海报。

## 10. 单关数据流

1. 客户端请求下一关公开数据并预加载图片。
2. 客户端请求开始该关；游戏服务创建唯一 round token，并在服务端调用 Cloudflare Worker 触发 AI 判断。
3. Worker 校验内部鉴权后调用 OpenAI Decisions API，并将标准化结果返回游戏服务；浏览器看不到 OpenAI Key、Worker 密钥或 Worker 内部地址。
4. 客户端收到开始响应后显示图片并启动倒计时。
5. 玩家点击或超时后提交 round token、选择位置和本地耗时。
6. 服务端只接受第一次有效提交，并依据服务端关卡答案结算玩家结果。
7. 若 AI 已完成，立即返回完整对比；否则短暂等待 AI，超过等待上限则先标记“AI 仍在判断”。
8. AI 最终结果异步落库；若本关揭晓时尚未完成，可在结算页补齐，但绝不修改玩家生命和到达关卡。
9. 服务端返回生命、下一关和本关展示数据。

AI 与玩家的启动同步允许小于 150 毫秒的网络误差。由于排行榜完全不使用速度，该误差不会影响竞争排名。

## 11. 异常与恢复

- 图片未加载完成：不开始倒计时，继续预加载或显示重试。
- 开始关卡接口失败：停留在关卡前，不消耗生命。
- 提交接口短暂失败：客户端锁定答案并幂等重试，不允许重新选择。
- 重复提交：服务端根据 round token 返回首次结算结果。
- 页面切后台：倒计时继续按绝对时间计算，防止暂停作弊。
- 页面刷新：恢复当前会话；已开始但未提交的关卡按超时处理。
- Decisions 超时、拒答、非法格式或 5xx：显示“AI 掉线”，玩家结果仍有效。
- Worker 不可用、鉴权失败或返回非法结构：按 AI 掉线处理并记录可观测错误码，不影响玩家生命和排行榜。
- 玩家网络中断：尚未显示的关卡不推进；已经显示的关卡依据服务端截止时间结算。
- 分享海报生成失败：仍允许复制普通结果链接。

## 12. 版本与难度校准

关卡集合使用 `levelSetVersion` 标识。一个正式版本发布后不修改图片、答案、位置或时限。

上线前使用首次挑战数据校准难度：

1. 内测收集至少 200 次有效首次挑战。
2. 查看每一关的到达率、正确率、超时率和中位作答时间。
3. 优先调整倒计时，其次调整差异显著度，不改变核心玩法。
4. 达到第 10 关存活率约 10% 后冻结 v1。
5. 后续若需要改变难度，发布新的关卡版本并使用独立排行榜，避免不同难度成绩混排。

## 13. 数据指标

核心漏斗：

- 首页到开始挑战转化率。
- 第 1、3、5、7、10、15、20 关存活率。
- 每关正确率、超时率与平均耗时。
- 每关玩家击败 AI 的比例。
- 完成一局后的重玩率。
- 结算页生成海报率、分享成功率和分享回流开始率。

事件至少包含：`game_start`、`level_shown`、`player_answered`、`ai_answered`、`level_result`、`run_end`、`replay`、`poster_generated`、`share_completed` 和 `share_landing_started`。

## 14. 测试与验收

### 14.1 关卡校验

- 每张图严格对应一个正确位置。
- 3×3 恰好生成 9 个候选，9×9 恰好生成 81 个候选。
- 正确答案存在于候选集合且只出现一次。
- 所有关卡在目标移动端尺寸下可点击、可辨认。

### 14.2 业务规则

- 三次错误或超时后结束游戏。
- AI 错误或掉线不扣玩家生命。
- 排行榜查询只使用到达关卡排序。
- 同关玩家返回相同名次。
- 无限重玩可以更新个人最好成绩。

### 14.3 Decisions 集成

- 使用可注入的假 Decisions 服务覆盖正确、错误、拒答、超时、非法候选、Worker 鉴权失败和 OpenAI 5xx。
- 对 Worker 进行契约测试，验证服务端鉴权、请求上限、候选校验、超时和日志脱敏。
- 进行真实 API 冒烟测试，验证游戏服务 → Cloudflare Worker → OpenAI 的完整链路，以及图片输入、81 个候选项、概率分布和置信度。
- OpenAI Key 只存在于 Cloudflare Worker Secret；Worker 鉴权密钥只存在于 Worker 与游戏服务环境变量，二者均不得进入 H5 包或浏览器网络请求。

### 14.4 端到端与性能

- 在 375×812、390×844 和 430×932 视口完成整局测试。
- 慢速网络下图片加载完成前不能启动倒计时。
- 单关切换的本地 UI 延迟目标低于 150 毫秒。
- 首屏只加载首页资源；开始后预加载当前关和下一关，避免一次下载全部资源。
- 分享落地页在不支持系统分享的浏览器中仍可复制链接和保存海报。

## 15. 首版明确不做

- 随机关卡或每日题目。
- 按耗时、生命或正确率排序。
- 登录、好友关系和多人房间。
- 道具、提示、复活广告和付费系统。
- 用户上传题目。
- AI 人为延迟或伪造结果。
- 原生 App；首版仅提供移动端 H5。
